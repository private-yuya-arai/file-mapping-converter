# DataMapping をタスクスケジューラで自動実行するための検討（v1.2）

作成日: 2026-11-07

## 1. 結論

- **「ユーザーがログオンしているときだけ実行」の形で登録する**（今の `タスク登録.bat` と同じ考え方）。ログオフ中に動かす形は、Microsoft が Office の無人自動化をサポートしていないため採用しない。
- ただし、今の `タスク登録.bat`（`schtasks /Create`）は**タスクの詳細設定を変えられない**。その結果、このPCでは次のことが起きる。
  - **ノートPCがバッテリー駆動中だと実行されない**（既定値が「AC電源のときだけ開始」）
  - **6:00 にPCがスリープ・電源オフだと、その日は実行されない**（既定値は「開始時刻を過ぎたら実行」がオフ）
  - **Excel が固まると最長 72 時間止まらず、その間の次回分も実行されない**
- このため、**登録は PowerShell の `Register-ScheduledTask` に切り替え**、詳細設定も一緒に指定することを勧める（案は「5. 登録方法の案」）。

## 2. 前提：このツールは「Excel マクロ」ではない

| 項目 | 内容 |
|---|---|
| 処理本体 | `DataMapping.vbs`（VBScript）。`cscript.exe` で実行する |
| Excel の使い方 | VBScript から Excel を**画面に出さずに起動**し（COM 経由）、設定の読み込み・Excel 入出力・TEXT 関数に使う |
| 設定ファイル | `DataMapping.xlsx`（**マクロなし**） |
| 終了コード | 0 = エラーなし / 1 = 停止した、またはエラーの日付がある |
| ログ | 実行ごとに `変換ログ_yyyymmdd_hhmmss.csv`（設定の「ログフォルダ」、空欄なら出力フォルダ） |

xlsm のマクロではないので、**マクロのセキュリティ設定・信頼できる場所の設定は関係ない**。必要なのは「Excel を COM で起動できるユーザーとして cscript を実行すること」だけ。

## 3. このPCで確認した環境

| 項目 | 値 | 影響 |
|---|---|---|
| Office | Microsoft 365（クイック実行）64bit、16.0.19127 | `System32\cscript.exe`（64bit）から問題なく起動できる（テストで確認済み） |
| PCの種類 | ノートPC（PCSystemType = 2） | バッテリー関連の設定が必要 |
| `C:\Windows\System32\config\systemprofile\Desktop` | なし | ログオフ中・SYSTEM で実行すると、Excel がブックを開けない典型的な状態 |
| 既存のタスク | `DataMapping*` は未登録 | — |
| 設定ファイルのパス | 入力・出力とも絶対パス（`C:\work\fileA` / `C:\work\fileB`） | 開始フォルダの影響を受けない（下の 4-4 参照） |

## 4. 検討した項目

### 4-1. どのアカウント・どの条件で実行するか

| 方式 | 内容 | 評価 |
|---|---|---|
| **A. ログオン中のみ実行**（`/IT`、LogonType = Interactive） | ログオンしているユーザーのデスクトップで実行。画面ロック中でも実行される | **推奨**。手動で実行したときと同じ条件で、テスト結果がそのまま当てはまる |
| B. ログオフ中も実行（パスワードを保存） | 画面のないセッションで Excel を起動する | 非推奨。Microsoft は Office の無人自動化をサポートしていない。ダイアログが出ると誰も閉じられず止まる。上の Desktop フォルダを作るなどの回避策が必要で、Office の更新で動かなくなることがある |
| C. SYSTEM アカウント | 同上。さらに Excel のライセンス認証がユーザー単位なので動かないことが多い | 不可 |

**方式 A の条件**：実行時刻にそのユーザーがログオンしていること（サインアウトしていると実行されない）。毎日動かすなら「専用PCを常時ログオン」か「担当者のPCで、サインアウトせずにロックで離席」のどちらかで運用する。

### 4-2. 今の `タスク登録.bat` の既定値で困る点

`schtasks /Create` で作ったタスクは、詳細設定が次の既定値になる（このPCで確認）。

| 設定（タスクのプロパティ） | 既定値 | 問題 | 推奨 |
|---|---|---|---|
| 条件：AC電源のときだけ開始 | オン | ノートPCがバッテリー駆動だと実行されない | **オフ** |
| 条件：バッテリーに切り替わったら停止 | オン | 実行中に電源を抜くと途中で止まる | **オフ** |
| 条件：スリープを解除して実行 | オフ | スリープ中は実行されない | 必要なら**オン**（ログオン中のスリープに限る） |
| 設定：開始時刻を過ぎたら、すぐに実行 | オフ | 6:00 に電源オフ・スリープなら、その日は実行されない | **オン** |
| 設定：実行時間の上限 | 72 時間 | Excel が固まると3日間止まらない | **1 時間**（このPCで 10万行が約 4 分。余裕を見て） |
| 設定：既に実行中のとき | 新しく開始しない | 上と組み合わさると、固まっている間の分が実行されない | そのまま |

### 4-3. Excel に関する注意

- **Excel のダイアログで止まる**：ツールは確認ダイアログを出さない設定で Excel を使うが、Office の更新・ライセンス認証・初回起動の案内などは画面に出ないまま待ち続けることがある。上の「実行時間の上限」で止める。
- **強制終了したときは EXCEL.EXE が残る**：上限で cscript が止められると、裏の Excel は終了されずに残る。タスクの結果が 0x0 以外のときは、タスクマネージャーで Excel が残っていないか確認する。
- **利用者が Excel を使っていても動く**：ツールは別の Excel を起動するので、作業中の Excel とは干渉しない。ただし**出力先の xlsx を開いていると、その日付はエラー**になる（テスト E9 で確認済み）。入力ファイルは読み取り専用で開くので、開いていても読める。

### 4-4. パス・開始フォルダ

- タスクスケジューラの既定の開始フォルダは `C:\Windows\System32`。設定ファイルのパスや、設定に書いたフォルダが**相対パスだと System32 から探してしまう**。
  - 今の設定は絶対パスなので問題ない。今後も**絶対パスで書く**。登録時に開始フォルダ（ツールのフォルダ）も指定しておく。
- **ネットワークドライブは `\\サーバー\共有` の形で書く**。ドライブ文字（`Z:` など）は、タスクの実行時に割り当てられていないことがある。
- `schtasks /TR` の実行コマンドは **261 文字まで**。フォルダの階層が深いと登録に失敗する（PowerShell の方法なら制限なし）。

### 4-5. 実行結果をどう知るか

- 今のままでは、エラーがあっても**誰にも通知されない**（タスクの「前回の実行結果」が `0x1` になるだけ）。
  - `0x0` = エラーなし / `0x1` = エラーあり（ログを確認）/ `0x41301` = 実行中
- 方法の候補（どれを採るかは要相談）
  1. 毎朝、担当者がログフォルダの最新ログと「前回の実行結果」を見る（追加の作業なし）
  2. エラー時に Windows のイベントログに書く（`eventcreate`）か、メールを送るラッパー bat を挟む
  3. タスクスケジューラの「すべてのタスク履歴を有効にする」をオンにし、履歴で実行の有無を追えるようにする（既定はオフのことが多い）

### 4-6. 繰り返し実行したときの動き（安全性）

- 設定「上書き」が**なし**なら、出力済みの日付は SKIP されるので、**同じ日に何度実行しても結果は変わらない**（テスト E2a で確認済み）。手動で再実行しても安全。
- v1.2 から、設定「対象日付」を**当日**にすると、実行した日の日付の fileA だけを変換する。入力フォルダに過去の fileA が残っていても、変換し直したりログに SKIP を並べたりしない（ログには「対象日付（当日（20261108））以外のファイル ○ 件は対象外」の1行だけ）。
  - 当日の fileA がまだ届いていなければ、エラー（終了コード 1）になる。届くより前の時刻にタスクを動かさない。
  - タスクの実行時刻と、fileA の名前の日付が同じ日であること（日付をまたいで届くファイルなど、前日分を朝に処理する運用なら要相談）。
  - 古い fileA は変換されなくなるが、フォルダの容量のため、古い fileA を別フォルダへ移す運用は決めておく。
- ログは実行ごとに1ファイル増える。毎日なら年に約 365 ファイル。定期的な削除を決めておく。
- 実行中にコンソール画面（黒い画面）が一瞬表示される（ログオン中のみ実行の仕様）。その時刻に作業していると気になる場合は、実行時刻を業務時間外にする。

### 4-7. 同じ日付の fileA が後から届いたとき（再出力の手順）

- fileA の名前は「番号_日付_時刻.csv」（例 `HSR38000_20261106_023902.csv`・`HSR38000_20261106_023908_1.csv`）。番号・時刻・連番が違っても同じ日付なら1つの fileB（例 `1_EL_出庫検索_20261106.csv`）にまとまる。
- その日付の fileB を出力した後に、同じ日付の fileA が届いた場合、設定「上書き」が**なし**なので、次の実行ではその日付が SKIP になる。後から届いた分は fileB に入らない。エラーにはならず、終了コードも 0 のまま。
- **運用：fileB を削除して再実行する**（コードの変更はしない）
  1. ログで、その日付が SKIP（出力ファイルが既にあるためスキップ）になっていることに気づく
  2. 出力フォルダのその日付の fileB（例 `1_EL_出庫検索_20261106.csv`）を削除する（Excel などで開いていれば閉じてから）
  3. `DataMapping_範囲実行.bat` をダブルクリックし、開始日にその日付を入力する（終了日は空欄でよい）
     - 設定「対象日付」が**当日**のときは、`DataMapping_実行.bat` や次回のタスク実行では**前の日付は変換されない**ので、必ず範囲実行で行う
     - 当日の分なら `DataMapping_実行.bat` でもよい
  4. ログがその日付の `OK … ○ ファイル → ○ 行 出力` になったことを確認する
- 条件と注意
  - 入力フォルダに、その日付の fileA がすべて残っていること（古い fileA を別フォルダへ移す運用にした場合は、戻してから実行する）
  - fileB を送信済みなら、作り直した fileB を送り直し、受け取り側で差し替えてもらう
  - ほかの日付の fileB は残っているので、作り直されない

### 4-8. 最初にまとめて作るとき（日付の範囲を指定して一括変換）

- 毎日のタスクは「対象日付＝当日」で動かし、それより前の日付の fileB は、最初に一度だけまとめて作る。
- **手順**
  1. 入力フォルダに、まとめて変換したい期間の fileA を置く
  2. `DataMapping_範囲実行.bat` をダブルクリックし、開始日・終了日を `yyyymmdd` で入力する（例 20261101 と 20261107）
  3. 完了メッセージとログで、日付ごとに `OK` になっていることを確認する
- 設定ファイルは書き換えない（コマンドラインの `/from:` `/to:` が設定の「対象日付」より優先される）。そのため、一括作成のあとに設定を「当日」へ戻し忘れることがない。
- コマンドから実行するときは次のとおり（`/to` を省くと `/from` の1日だけ）。
  ```
  DataMapping_範囲実行.bat 20261101 20261107
  cscript //nologo DataMapping.vbs "C:\path\DataMapping.xlsx" /from:20261101 /to:20261107
  ```
- 設定で決めたい場合は、「対象日付」を**範囲**にして「対象日付_開始」「対象日付_終了」を入れる。ただし、毎日のタスクも同じ設定ファイルを使うなら、終わったら必ず**当日**に戻す。
- 既に fileB がある日付は、「上書き＝なし」ならスキップされる（作り直したい日付は、先に fileB を削除する）。

### 4-9. fileA・fileB のファイル名（時刻つき）

- **fileA：** 名前の中で最初に出てくる8桁の数字を日付として使う。後ろに時刻や連番が付いていてもよい（例 `HZR17002_20261108_023239_3.csv` → 20261108。テスト J7 で確認済み）。
  - 番号が8桁以上になると番号を日付と誤るので、その場合は設定「日付抽出パターン」を `_(\d{8})_` にする。
  - `2026-11-08` のような区切り入りの日付は読めない（ログに SKIP）。
- **fileB：** 設定「出力ファイル名」は自由に決められる。`{date}` は必須で日付に置き換わり、`{time}` を書くと**変換した時刻**が付く。
  - 例 `HZR_送信_{date}_{time}_B.csv` → `HZR_送信_20261108_160835_B.csv`（`{time}` を書かなければ時刻なし）
  - 時刻は実行を始めた時刻で、1回の実行で出す fileB にはすべて同じ時刻が付く。書式はシステム設定「出力ファイル名_時刻書式」（既定 `hhmmss`。`:` などファイル名に使えない文字になる書式は設定エラー）。
  - **注意：** `{time}` を付けると、実行のたびに名前が変わる。そのため「上書き＝なし」でも出力済みの日付が SKIP にならず、同じ日付を2回実行すると fileB が2つできる（テスト J6）。
    - 毎日のタスクは「対象日付＝当日」なので、同じ日に2回動かさなければ問題ない。手動で再実行したときは、古い fileB を消すか、送らないようにする。
    - 4-7 の再出力では、古い fileB を消さなくても新しい名前で出力される（古い方は送らない・削除する）。

## 5. 登録方法の案（PowerShell）

今の `タスク登録.bat` の代わりに使う案（**まだ作成・登録はしていない**）。フォルダとタスク名・時刻は実際の運用に合わせる。

```powershell
$dir  = 'C:\workspace\files\v1.0'
$tool = Join-Path $dir 'DataMapping.vbs'
$cfg  = Join-Path $dir 'DataMapping.xlsx'

$action = New-ScheduledTaskAction -Execute "$env:SystemRoot\System32\cscript.exe" `
            -Argument "//nologo `"$tool`" `"$cfg`"" -WorkingDirectory $dir
$trigger = New-ScheduledTaskTrigger -Daily -At '06:00'
# ログオン中のみ実行（パスワードを保存しない）
$principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType Interactive
$settings = New-ScheduledTaskSettingsSet `
            -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
            -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Hours 1) `
            -MultipleInstances IgnoreNew
            # スリープ中も起こして実行するなら -WakeToRun を追加

Register-ScheduledTask -TaskName 'DataMapping_日次変換' -Action $action -Trigger $trigger `
    -Principal $principal -Settings $settings -Force
```

- 管理者権限は不要（自分のユーザーで実行するタスクのため）。
- 登録後は `Start-ScheduledTask -TaskName 'DataMapping_日次変換'` で1回動かし、「前回の実行結果」とログを確認する。
- 既に GUI や `タスク登録.bat` で登録済みなら、GUI で 4-2 の推奨値に変えるだけでも同じ効果がある。
